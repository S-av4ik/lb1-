Технічне завдання: Task Tracker API
1. Вступ

Task Tracker — невеликий сервіс на Flask, який зберігає список завдань. Через нього можна додати, переглянути, змінити і видалити завдання.

2. Мета і задачі
Мета: зробити простий сервіс і на його прикладі пройти весь процес: ТЗ, версії, релізи.
Задачі:
зробити роботу із завданнями (додати, переглянути, змінити, видалити);
зробити перевірку, що сервіс працює (/health);
вести версії за SemVer і гілки за GitFlow.
3. Цільова аудиторія

Студенти та розробники, яким потрібен простий список завдань через HTTP. Сценарії: додати завдання, переглянути список, позначити виконаним, видалити.

4. Функціональні вимоги
Перевірка стану: GET /health повертає статус і версію. Приймання: код 200.
Створення: POST /tasks з полем title. Приймання: код 201; порожній title — код 400.
Перегляд: GET /tasks і GET /tasks/<id>. Приймання: якщо id немає — код 404.
Зміна: PUT /tasks/<id> (title, done). Приймання: код 200, зміни збережені.
Видалення: DELETE /tasks/<id>. Приймання: код 204; повторне видалення — 404.
5. Нефункціональні вимоги
Швидкість: відповідь менше 200 мс.
Безпека: перевірка вхідних даних; авторизацію (OAuth2) додамо пізніше.
Сумісність: Python 3.10+, Windows/Linux/macOS.
Логування: запити виводяться в консоль, є /health.
6. Обмеження та припущення
Технології: Python, Flask, pytest, Git, GitHub Actions.
У версії 1.0.0 дані зберігаються в пам'яті, бази даних немає.
Проєкт навчальний, його робить 1 людина.
7. Інтерфейс користувача

Графічного інтерфейсу немає, усе через HTTP і JSON. Приклад: POST /tasks → GET /tasks → PUT /tasks/1 → DELETE /tasks/1.

8. Архітектурні рішення
Сервер: один файл app.py на Flask.
БД: немає (у версії 2.0.0 можна додати SQLite).
CI/CD: GitHub Actions запускає тести, а при новому теґі створює реліз.
9. План робіт та етапи
Ітерація 1: каркас проєкту, /health, налаштування CI.
Ітерація 2: робота із завданнями (CRUD) і тести.
Ітерація 3: документація, виправлення, підготовка релізу.
Реліз 1: версія v1.0.0.
