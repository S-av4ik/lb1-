# Звіт до лабораторної роботи №1

**Тема:** технічне завдання, модель життєвого циклу, версіонування, шаблони.
**Проєкт:** Task Tracker API (невеликий сервіс на Flask для списку завдань).

## Що зроблено
1. Заповнив технічне завдання за шаблоном (`ТЗ.md`).
2. Обрав модель Agile (Scrum) зі спринтом на 1 тиждень. Обґрунтування є в `README.md`.
3. Описав версіонування: SemVer і GitFlow (`VERSIONING.md`).
4. Зробив шаблони: release notes, changelog, чекліст приймання.
5. Показав роботу з Git:
   - дві гілки `feature/add-health-endpoint` і `feature/add-tasks-crud`;
   - злиття їх у `develop` через `--no-ff`;
   - злиття у `main` і тег `v1.0.0`;
   - гілка `hotfix` і тег `v1.0.1`.
6. Додав GitHub Actions: автоматичний запуск тестів і створення релізу при новому теґі.


## Висновки
 Чітке ТЗ із критеріями приймання допомагає зрозуміти, коли робота готова.
 За номером версії одразу видно, що змінилось: нова функція, виправлення чи несумісна зміна.
 Окремі гілки для фіч не дають зламати стабільний код, а `--no-ff` залишає в історії видимі злиття.
 Теги разом із CHANGELOG показують історію релізів, а CI автоматично перевіряє тести й створює реліз.
