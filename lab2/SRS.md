# Лабораторна робота №2
**Тема:** визначення, аналіз та специфікація вимог до інформаційної системи
**Задача:** інформаційна система для онлайн-замовлення їжі

## 1. Вступ
Система дозволяє клієнтам замовляти їжу в ресторані через сайт, а працівникам ресторану — приймати й обробляти замовлення. Документ описує вимоги до системи.

## 2. Бізнес-вимоги
- BR-1. Збільшити кількість замовлень за рахунок зручного онлайн-замовлення.
- BR-2. Зменшити навантаження на працівників, які приймають замовлення по телефону.
- BR-3. Зменшити кількість помилок у замовленнях.

## 3. Користувацькі вимоги
- UR-1. Клієнт може зареєструватися і увійти в особистий кабінет.
- UR-2. Клієнт може переглядати меню та шукати страви за назвою або категорією.
- UR-3. Клієнт може додати страви в кошик і оформити замовлення.
- UR-4. Клієнт може оплатити замовлення онлайн або при отриманні.
- UR-5. Клієнт може бачити статус замовлення та історію своїх замовлень.
- UR-6. Адміністратор ресторану може змінювати меню та обробляти замовлення.

## 4. Системні вимоги

### 4.1. Функціональні
| ID | Вимога | Пов'язано з |
|----|--------|-------------|
| FR-1 | Система має форму реєстрації та входу (email і пароль) | UR-1 |
| FR-2 | Система показує меню з пошуком і фільтром за категорією | UR-2 |
| FR-3 | Система має кошик: додати, видалити страву, змінити кількість | UR-3 |
| FR-4 | Система створює замовлення з адресою і часом доставки | UR-3 |
| FR-5 | Система приймає онлайн-оплату карткою або фіксує оплату при отриманні | UR-4 |
| FR-6 | Система показує статус замовлення («прийнято», «готується», «доставляється», «виконано») | UR-5 |
| FR-7 | Система надсилає клієнту email про зміну статусу замовлення | UR-5 |
| FR-8 | Адміністратор може додавати, змінювати й видаляти страви в меню | UR-6 |

### 4.2. Нефункціональні
| ID | Вимога |
|----|--------|
| NFR-1 | Продуктивність: система витримує не менше 500 одночасних користувачів |
| NFR-2 | Час відгуку на пошук страв — не більше 2 секунд |
| NFR-3 | Безпека: паролі зберігаються у зашифрованому вигляді, дані передаються через HTTPS |
| NFR-4 | Захист персональних даних відповідно до GDPR |
| NFR-5 | Надійність: доступність сайту не менше 99% часу |
| NFR-6 | Сумісність: працює в сучасних браузерах (Chrome, Firefox, Edge) і на телефоні |
| NFR-7 | Зручність: оформити замовлення можна не більше ніж за 5 кроків |

## 5. Обмеження та припущення
- Доставку виконує сам ресторан, інтеграція зі службами доставки не потрібна.
- Для онлайн-оплати використовується готовий платіжний сервіс.
- Система розрахована на один ресторан.

## 6. Відповіді на питання для самоконтролю
1. **Що таке вимога?** Це опис того, що потрібно користувачам чи бізнесу і що має робити або якою має бути система.
2. **Бізнес- і користувацькі вимоги.** Бізнес-вимоги описують цілі організації (наприклад, більше замовлень), а користувацькі — що саме може зробити користувач у системі.
3. **Приклади нефункціональних.** Швидкість відповіді, кількість користувачів, безпека, надійність, сумісність з браузерами.
4. **Методи збору вимог.** Інтерв'ю, опитування, спостереження, аналіз документів, прототипування.
5. **Що таке SRS.** Це документ зі специфікацією вимог. Зазвичай містить вступ, опис системи, функціональні й нефункціональні вимоги та обмеження.
